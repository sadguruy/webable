## Why this library exists

Applications repeat the same core UI patterns again and again: buttons,
inputs, tabs, tables, alerts, and form controls. Webable is meant to keep
those pieces consistent, accessible, and easy to share across React-based
projects.

## Component direction

The library is intended to cover common UI patterns such as:

- `Button` components for primary, secondary, warning, error, and destructive actions
- `Input` components for text entry, validation states, and form workflows
- `Tabs` for grouped content and compact navigation
- Data display components such as tables, badges, and status indicators
- Layout helpers and utility building blocks for consistent composition

## Current focus

The current component set starts with **ActionButton**, which establishes the
pattern for:

- Variant-driven styling
- Reusable sizing and width options
- Optional icon support
- Strong defaults that still stay flexible

## How to use Storybook here

1. Review component variants and interaction states
2. Test API options before using components in product code
3. Document new components as the library grows

## Goal

Webable aims to stay lightweight in bundle impact and easy to adopt, while
still giving teams a reliable shared UI layer for React applications.
